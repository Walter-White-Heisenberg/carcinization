# E1：独立的十轮开发观察

E1 使用与完成的 E0 相同的固定开发论文、官方 OpenAI 接口、`gpt-6.1-sol` 提供者默认参数和 32768 输出 token 上限。它重新生成三个独立起点，再对接力和无历史两条件各更新十轮，共 63 个计划生成槽。E0 原始材料和冻结源码不改动，旧审稿不复用到新轨迹。

`development_e1.py` 在独立模块实例中复用已有协调器的原始请求/响应登记、父记录、临时错误最多重试两次、崩溃恢复、预算预留和 P00E/P09 自动标注。E1 明确提供自己的运行校验、十轮顺序和 0–10 轮分析，不把 E1 伪装成 E0，也不改变正式 pilot 入口。

## 当前准备状态

本地新 run 为 `e1_20261118_gpt61_default_001`。论文输入和 63 槽顺序已准备；尚无真实 API 尝试。累计费用包括四个旧 E0 run 的全部已知费用及未知费用预留，当前合计约 USD 3.090。配置中的新累计上限和对应用户指令仍为空，代码会在读取凭证、创建冻结快照和发送请求之前拒绝执行。

## 运行方法

```powershell
python experiment/src/development_e1.py prepare
python experiment/src/development_e1.py preflight
python experiment/src/development_e1.py run --limit 1
python experiment/src/development_e1.py run
python experiment/src/development_e1.py report
```

`prepare` 只做离线准备，重复调用不覆写配置。实际执行前，在新 run 的 `config.json` 记录用户明确给出的累计 USD 上限和原指令，核实当日官方价格并更新计价记录。模型、论文和默认参数不变。公开源码导出不含旧 run 输入；从该导出运行前需自行提供相同版本、可检查的开发论文和对应来源记录。

先用一个真实计划槽核对原始请求与响应、谱系和费用，再从同一日志继续固定顺序。预算不足、中断和失败如实保留，不补抽起点、不复用失败文本、不因曲线方向调整轮数。自动结构测量逐轮报告 D、C、ΔC；缺少任何必要轨迹时保留缺失。

## 质量与证据

论文保持固定，E1 不测文章改稿质量变化。审稿科学质量作为另行标注的探索性 AI 来源审计处理；没有独立人工裁决就不写作人审。若没有生成前冻结、经核实的问题清单，已知问题召回率不可用；若没有已确认错误项，错误持续率不可用。两者均不能填零。

六篇论文的跨论文批次与 E1 分开。近期公开不证明未进入训练集；三条轨迹和十轮均不是额外独立论文。正式 pilot 的人工端点要求保留，现阶段的自动探索分析不能替代这些端点。
